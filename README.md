# s0L Deal Tracker

## Root Policy
Only keep runtime entrypoints, configuration, and canonical data at root.

### Keep at root
- `deal_tracker.py`
- `deal_structure.py`
- `deals_data.json`
- `core/`
- `frontend/`
- `documents/`
- `assets/`
- `package.json`, `package-lock.json`, `requirements.txt`

### Do not keep at root
- ad-hoc analysis scripts
- generated build output
- temporary exports and scratch files

## Folder Purpose
- `core/`: backend API (feature + shared layout)
- `frontend/`: React app (feature + shared layout)
- `documents/`: ingested/generated document artifacts used by app
- `assets/reference/`: human reference source files (docx/xlsx/pptx)

## Commands
- Install all: `npm run install:all`
- Run app: `npm run dev`
- Verify builds/imports: `npm run verify`
- Cleanup generated residue: `npm run clean`
- Deep cleanup including rendered slide folders: `npm run clean:deep`
- Build the signed portable app: `npm run package` (sign in first: `az login --tenant 53766e3f-8ad5-418c-bac7-aaad7bdc46df --use-device-code`). Output: `release\s0L-<version>.zip`. Test builds: `npm run package:unsigned`.

## Notes
- `npm run dev` fails if ports `5120` or `5121` are already in use.
- `npm run clean:deep` removes generated `documents/*_slides` folders and they can be regenerated by re-processing documents.
- The real iSBD reference deck (`frontend/src/features/isbd/isbdReference.json`, `frontend/public/isbd-bg/ref_slide*.png`) contains client deal content and is gitignored. A fresh clone uses the blanked `isbdReference.sample.json`; copy the real files in for the full reference view. `npm run package` holds them aside, so they never ship.
- Colleagues unzip the package and double-click `s0L.exe`; their data lives in `%LOCALAPPDATA%\s0L`, so a new version is just a new folder.
